# 横截面选股：固定评估器 v2（本地打磨 → 尾部 holdout → 聚宽 point-in-time 终验）

本文定义「方向 2（横截面 / 多标的选股）」的设计。目标是把 HL 循环从单标的择时
扩展到**在股票池里排序选股取超额 alpha**，用一台**物理隔离、口径冻结、可复现**的
v2 评估器支撑随时迭代。单标的版（`strategy.py` / `backtest.py`）**原封不动**，两台
引擎并存。

> 命名：`xs` = cross-sectional（横截面），量化里指「同一时刻横向比较一批股票、
> 排序选股」，区别于单标的沿时间轴的纵向择时。

## 为什么做横截面

单标的择时（方向 1）的结构性结论：单一宽基指数 8 年只有约 1-2 段趋势，任何择时
策略的盈亏都被这 1-2 段主导（profit factor≈1、有效交易个位数），**独立下注样本
太少，立不住稳健 edge**（见 `hl-ledger.md` Round 3/4）。横截面把「一个标的的时间
序列下注」变成「每次调仓在几十只股票里做横向选择」，月度 × 8 年 ≈ 76 次调仓 ×
Top 3 ≈ 228 次持仓，独立下注数提升一个数量级，才谈得上可统计的选股 alpha。

## 锁定的设计决策

| 维度 | 决策 | 说明 |
| --- | --- | --- |
| 成功目标 | **相对基准的超额 alpha** | score = 信息比率 IR，不是绝对 Sortino |
| 股票池 | **沪深300 成分固定快照** | 硬编码约 300 只代码清单；接受幸存者偏差、显式标注 |
| 基准 | 沪深300 指数（腾讯 `sh000300`） | 与股票池对齐 |
| 组合 | **月度调仓、等权持有 Top 3** | 与 10 万实盘可执行性对齐；集中度高，特异性风险大（标注） |
| 起始因子 | **横截面动量** | 过去约 12 个月（跳过最近 1 月）累计收益 |
| 样本外 | **单一尾部 holdout（最近 ~20%）** | 跑通闭环后再考虑升级为滚动多折 walk-forward |

## 架构与数据流

```
沪深300 成分固定快照（约300只代码，硬编码清单，含标注）
        │
        ▼
load_panel()  ── 腾讯日线 OHLC，逐只拉取+本地缓存（复用单标的版分页逻辑）
        │        产出「日期 × 股票」的 open/close 面板 + 基准 sh000300 日线
        ▼
run_backtest(panel)  ── 固定评估器 v2，逐月循环：
   每个调仓日（每月首个交易日 T）:
     1. 取「≤ T-1 收盘」的历史喂给 strategy_xs.score(history) → {股票:分数}
     2. 引擎排序取 Top 3、剔除停牌/当日涨停无法买入者、等权分配目标市值
     3. T+1 开盘按目标调仓（卖不再持有的、买新入选的），扣佣金/印花/滑点/整手
     4. 其余交易日按收盘估值，记组合日净值
        │
        ▼
_compute_metrics(组合净值, 基准净值)  ── 超额/IR 口径打分
```

- **月度调仓、日度估值**：只在每月首个交易日调仓，其余日子持仓不动、按收盘算净值
  （回撤/波动保持日度精度）。
- **复用数据层**：`load_panel` 复用单标的版的腾讯分页+缓存逻辑，逐只拉、缓存到
  `.cache/`。首次拉约 300 只较慢，之后读缓存。
- **职责分离**：策略只决定「打分」，引擎决定「排序/选择/调仓/成本」，与单标的版
  「strategy 管信号、backtest 管撮合」一脉相承。

## 唯一可编辑接口（`example/strategy_xs.py`）

只暴露一个**纯打分函数**，签名固定：

```python
LOOKBACK = 252         # 需要的历史交易日数（引擎据此喂数据、留 warmup）
REBALANCE = "monthly"  # 声明式，仅供引擎读取；调仓节奏由引擎固定执行

def score(history: dict[str, pd.DataFrame]) -> dict[str, float]:
    """输入：{股票代码: 截至调仓日前一日的 OHLC DataFrame}（只含已完成 bar，无未来数据）。
    输出：{股票代码: 分数}，分数越高越优先。引擎对分数排序取 Top 3、等权。
    纯函数：只看价格、只给分数；不下单、不读盘、不联网、不碰权重与成本。"""
```

- **HL 每轮只改这个函数体**（动量 → 动量+低波 → 加过滤……），引擎/成本/调仓/口径
  一律不动。
- 起始基线：`score = 约21日前收盘 / 约252日前收盘 − 1`，即跳过最近约 1 个月的
  「12-1 动量」（经典动量，跳过最近 1 月规避短期反转）；窗口恰好用满 `LOOKBACK=252`。
- 用 `# >>> STRATEGY CORE >>>` / `# <<< STRATEGY CORE <<<` 标记包裹，供
  `export_jq_xs.py` 原样注入聚宽——与单标的版相同的单一事实源机制。
- **约束**：CORE 段只依赖 `pandas`，不做文件 IO / 联网 / 本地 import；窗口 ≤ `LOOKBACK`。

## score 口径（相对基准的超额 alpha，冻结）

```
组合日超额收益 rₑ(t) = 组合日收益(t) − 沪深300日收益(t)
score = 信息比率 IR = mean(rₑ) / std(rₑ) × √252
```

- **主 score = 信息比率 IR**：每单位跟踪误差换来的超额，是横截面 alpha 的标准尺子。
- 同时报告并作**验收门槛**（预登记，见下）：年化超额、超额最大回撤、月度胜率
  （跑赢基准的月份占比）、年换手、有效持仓月数。
- 不用 Sortino 的原因：单标的看绝对风险调整；横截面选股天职是相对指数取 alpha。

## 科学固定评估器：反过拟合与实盘约束

评估器要「骗不了你、可随时复现」，靠以下硬约束（全部固化在 `backtest_xs.py`，与
strategy 物理隔离，改它=作弊）：

**A. 固定研究口径（冻结区）**
池子（300 只固定快照清单）、区间（2018-01-01~2026-02-28）、基准（`sh000300`）、
调仓频率（月度）、N=3、等权、成本、滑点、随机种子——全部硬编码。

**B. 无未来数据（point-in-time 纪律）**
调仓日 T 只用「≤ T-1 收盘」的数据打分，**T+1 开盘成交**（与单标的版一致），杜绝
用当日/未来数据选股。

**C. 单一尾部 holdout（对齐反过拟合机制）**
- 全窗口打分（研究用）＋ 尾部 holdout（最近 ~20%，**run-once** 样本外确认）。
- 实际切分（按交易日历，1976 日，20%）：
  - **样本内（训练）**：2018-01-02 ~ 2024-07-08（1580 日，约 6.3 年，≈228 次持仓）
  - **holdout**：2024-07-09 ~ 2026-02-27（396 日，约 1.6 年，≈57 次持仓）
- 泛化门槛：`训练 IR − holdout IR` 过大即判过拟合拒绝。
- **样本量门槛**：有效下注 = 调仓次数 × 平均持仓数，低于下限（暂定 < 100 次持仓）
  判无效。
- **已知局限**：holdout 落在 2024-09 强反弹这一单一 regime，通过不代表全天候稳健；
  后续可升级为滚动多折 walk-forward（本期不做）。

**D. 实盘约束（对齐聚宽 / A股）**
T+1、100 股整手、佣金万3/卖出印花千1/最低5元、滑点 0.00246；停牌股不参与调仓、
当日涨停买不进则顺延下一名；10 万资金、等权 Top 3（每只约 3.3 万），不含科创板。

**E. 幸存者偏差（诚实标注 + 终验兜底）**
本地用「今日成分固定快照」跑通，评估器文档与输出**显式标注该偏差方向（偏乐观）**；
最终无偏结论用聚宽 `get_index_stocks(日期)` 的 point-in-time 成分在平台复跑。

**F. 可复现**
固定随机种子、纯函数打分、缓存数据带区间指纹；同输入必同输出；`harness.sh` 纳入
v2 的一致性校验（`export_jq_xs.py --check`）。

**G. 分红处理（本地口径 + 与聚宽的差异，显式标注）**
- **本地（腾讯前复权 qfq）**：前复权把历史价按分红/送转向下调整，除权日不留跳空，
  等价于「分红按除权价**即时复投到同一只股票**」——本地净值跑的是**全收益（total
  return）**，分红隐含在价里，无现金落袋、无下跳。
- **聚宽（`use_real_price=True`）**：真实价，除权日价格下跳、分红以**现金**入账；在
  等权 Top 3、月度调仓下现金**闲置至下次调仓**才被重新分配。
- **差异分层**：
  1. 因子层（动量排序）：前复权是**正确**基准（含分红全收益，避免高股息股除权日
     假摔污染动量），这一层本地更对，不改。
  2. 记账层：本地=即时复投同股，聚宽=现金落袋闲置≤1 月；沪深300 股息率约 2~3%/年，
     复投时点差是**二阶小量**。
  3. 红利税：A股按持有期计（<1 月 20%、1 月~1 年 10%），月度调仓约持 1 月，聚宽若
     计税有额外拖累、本地前复权不计——**方向上本地偏乐观**，量级约 0.2~0.5%/年。
- **v2 决策**：保持前复权做因子与记账（对因子正确、实现简单），分红残差显式标注为
  已知缺口，由聚宽真实价 point-in-time 终验去暴露。**不在本期建本地现金分红模型**
  （需逐股分红事件源 + 按持仓期算红利税，复杂度陡增，属 YAGNI）；若终验显示差距被
  分红显著放大，再作为升级项补建。

## 预登记验收门槛（冻结后不临场心证）

IR 有抽样噪声，门槛挂在**样本长度**上：超额 t 统计量 ≈ `IR × √年数`。全窗口 8.06 年
→ `t = IR×2.84`，t≥2 需 IR≥0.70；holdout 仅 1.57 年 → `t = IR×1.25`，即使 IR=1.0 也
只有 t≈1.25，故 **holdout 天生做不了显著性检验，只能做「符号/不退化」检查**。全窗口
IR 标准误 ≈ `√((1+IR²/2)/年数)`（IR≈0.7 时约 0.39），单点 IR 本就飘——因此不能只比
一个 IR 数字，必须叠加样本外一致性 + 不靠单点 + 参数高原。

精神：**迭代阶段宽进**（真比基线好、样本外不塌、不靠单点即可继续），**部署阶段严出**
（必须统计显著 + 样本外为正才合入 main）。

### 第一级 — 每轮「接受、继续迭代」

| 门槛 | 判据 |
| --- | --- |
| **主 score = IR** | 全窗口 IR **严格 > 基线**（硬门槛） |
| holdout 不塌 | holdout IR ≥ 0，且 `样本内 IR − holdout IR` ≤ 1.0（> 1.0 判过拟合拒绝） |
| 不靠单点（Round 3 教训） | 最大「单只 × 单期」对累计超额贡献 ≤ **30%** |
| 参数高原（Round 4 教训） | Top-N 邻域 N∈{2,4,5} 与因子窗口 ±20% 内 IR 不塌成尖峰 |
| 广度 | 有效持仓次数（调仓数 × 持仓数，全窗口）≥ **100** |

### 第二级 — 「合入 main / 部署级」额外要求

| 门槛 | 判据 |
| --- | --- |
| 统计显著 | 全窗口超额 **t ≥ 2**（≈ IR ≥ 0.70），alpha 非噪声 |
| 样本外为正 | **holdout IR > 0** |

### 报告项（不设硬门槛，只供判断；软容忍带已放宽）

年化超额（≥ 基线 −5%）、超额最大回撤（≤ 基线 **+5pp**）、月度胜率（≥ 基线 **−5pp**）、
年换手、每次可选股数。放宽理由：Top-3 集中度高、这些指标方差大，沿用 ±2~3pp 会频繁
误杀；严格性已放到显著性 + holdout + 不主导 + 高原上。

### 多重检验纪律

账本记录**累计尝试轮数**；尝试越多越该信 holdout、越该压 IR 上偏。第二级 `t≥2`
显著性门槛正是对抗「试很多次挑出的高 IR 天然上偏」。未来可升级 Deflated Sharpe/IR
做正式多重检验校正（本期先用 t≥2 + holdout 兜底）。

## 已知缺口（诚实标注，不在本地假装消除）

1. **幸存者偏差**：本地固定快照偏乐观；靠聚宽 point-in-time 终验兜底。
2. **分红/价格口径二阶残差**：本地前复权（分红即时复投）vs 聚宽真实价+现金分红
   （落袋闲置+可能红利税），方向上本地略乐观（约 0.2~0.5%/年），见上「G. 分红处理」。
3. **单一 regime holdout**：尾部 1.6 年偏牛市；后续升级滚动多折再补跨 regime 稳健性。
4. **Top 3 集中度**：个股特异性风险大，一只踩雷影响明显；由等权 + 月度再平衡部分缓释。

## 改策略后的标准流程

1. 只改 `strategy_xs.py` 的 STRATEGY CORE（仅依赖 pandas、窗口 ≤ LOOKBACK）。
2. `python backtest_xs.py` 全窗口打分；`--holdout` 看样本内 vs 尾部样本外。
3. `python scripts/export_jq_xs.py` 重新生成聚宽脚本。
4. `./scripts/harness.sh` 通过后提交。
5. 候选冻结后，在聚宽平台用 point-in-time 成分跑一次全窗口终验（run-once）。
